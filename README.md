# 개발 환경 구축 미션
터미널, Docker, Git/GitHub를 활용하여 개발 워크스테이션 환경을 직접 구성하고, 그 과정과 결과를 기술 문서 형태로 정리.

1번 미션에서는 다음 항목을 중심으로 작업을 진행.

- 터미널로 작업 디렉토리 및 파일을 다루는 기본 조작 수행.
- 파일과 디렉토리의 권한 확인 및 변경 실습.
- Docker 설치 및 데몬 동작 여부 점검.
- hello-world 및 ubuntu 컨테이너 실행과 기본 운영 명령 확인.
- Dockerfile 기반 커스텀 이미지 제작.
- 포트 매핑을 통한 브라우저 접속 확인.
- 바인드 마운트로 호스트 변경 사항이 컨테이너에 즉시 반영되는지 검증.
- Docker 볼륨을 이용한 데이터 영속성 확인.
- Git 사용자 설정 및 원격 저장소 연결 상태 확인.

파일의 권한은 크게 세 가지로 나뉩니다.

| 기호 | 의미 | 파일에서의 역할 | 디렉토리에서의 역할 | 점수 |
| :--: | :--- | :--- | :--- | :--: |
| **r** | **Read (읽기)** | 파일 내용 보기 (`cat`, `vi`) | 내부 파일 목록 보기 (`ls`) | **4** |
| **w** | **Write (쓰기)** | 파일 내용 수정 및 저장 | 파일 생성, 삭제, 이름 변경 | **2** |
| **x** | **Execute (실행)** | 스크립트나 프로그램 실행 | 디렉토리 내부로 진입 (`cd`) | **1** |

## 2. 권한 구조 분석

`ls -l` 명령어를 입력했을 때 나타나는 권한 문자열을 분석합니다.

> 예: `-rwxr-xr--`

1. **첫 번째 칸 (`-`)**: 파일 타입 (`-`는 파일, `d`는 디렉토리)
2. **2~4번째 (`rwx`)**: **소유자(User)** 권한 - 내가 할 수 있는 것
3. **5~7번째 (`r-x`)**: **그룹(Group)** 권한 - 같은 그룹원이 할 수 있는 것
4. **8~10번째 (`r--`)**: **나머지(Others)** 권한 - 그 외 모든 사람이 할 수 있는 것

## 3. 권한 변경 방법 (chmod)

### ① 심볼릭 모드 (Symbolic Mode)
문자를 사용하여 특정 대상의 권한을 변경합니다.
- **대상**: `u`(user), `g`(group), `o`(others), `a`(all)
- **연산자**: `+`(추가), `-`(제거), `=(설정)`

```bash
chmod u+x script.sh   # 소유자에게 실행(x) 권한 추가
chmod g-w file.txt    # 그룹의 쓰기(w) 권한 제거
chmod o=r file.txt    # 나머지는 읽기(r)만 가능하게 설정
